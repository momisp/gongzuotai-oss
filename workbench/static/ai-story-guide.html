0 先搞清它是干什么的

AI Story 把「写文案 → 分镜 → 出图 → 运镜 → 成片」拆成流水线。你负责提供剧情与模型 API，它负责按阶段调用模型并串起来。

文案改写→ 分镜脚本→ 白模预演（可选）→ 文生图→ 运镜→ 图生视频
作用：每一阶段用不同能力的模型。文案/分镜用 LLM；出图用文生图；成片用图生视频。混用 Mock 或类型不对，就会「看起来跑了但结果是假的 / JSON 解析失败」。
许可证：CC BY-NC-SA 4.0，仅个人学习 / 非商业。上游 API（如火山方舟）按各家计费与额度，与豆包网页版额度不是同一套。

1 启动服务

  1. 确认本机已安装并打开 Docker Desktop。
  2. 在工作台「AI Story」页点 启动 Docker，或运行 integrated/ai_story/start.bat。
  3. 点 刷新状态，看到「服务已就绪」、地址为 http://127.0.0.1:3000。
  4. 再点 进入使用 / 工作台内打开。
作用：拉起 frontend（网页）、backend（接口）、celery（后台跑流水线）、redis。没就绪时打开模型页会出现「加载内置厂商失败」、502。
若反复 Restarting：多半是库里 Mock 提供商重复导致启动崩溃。回到工作台刷新状态；仍不行可在部署目录执行 docker compose ps / docker compose logs backend 排查。

2 登录 / 建管理员

首次部署需要管理员账号，否则接口会 401，页面像「没模型」。

cd integrated/ai_story
docker compose exec backend python backend/manage.py createsuperuser
  1. 按提示设置用户名、邮箱、密码。
  2. 浏览器打开 http://127.0.0.1:3000 登录。
作用：项目、模型、提示词都挂在登录用户下；未登录只能看到空壳或报错。

3 配置真实模型（最关键）

路径：AI Story → 模型管理。

3.1 停用 Mock（强烈建议）

  1. 搜索 mock，找到 Mock LLM / Text2Image / Image2Video。
  2. 对它们点 停用（不必删；删了重启可能又自动建回来）。
作用：系统默认提示词模板会指向 Mock。Mock 只返回占位内容，分镜常不是合法 JSON，流水线会失败。停用后自动兜底不会再优先选到它。

3.2 加载 / 确认火山等真实厂商

  1. 用「加载内置厂商」或新建提供商，配好火山方舟等。
  2. 工作台「AI Story」页可复制 LLM 的地址 / 模型 / Key（文案、分镜用）。
  3. 出图、视频要在 AI Story 里单独配文生图、图生视频模型（和聊天 LLM 不是同一个能力）。
阶段需要的模型类型说明
文案改写 / 分镜 / 运镜LLM可用工作台复制的方舟 Chat 配置
文生图文生图如 Seedream 等，需对应 API
图生视频图生视频如 Seedance / wan i2v，需对应接口与额度
关于「优先级」：数字越大越优先。Mock 默认常为 100，火山多为 0。停用 Mock 后一般够用；若仍被抢，可把常用真实 LLM 优先级调到 >100。优先级不等于「给某个作品点选模型」。

4 改提示词模板里的默认模型

路径：AI Story → 提示词 → 打开「默认提示词模板集」（建议先克隆一份再改，避免部署重置）。

  1. 进入每个阶段模板（分镜、文生图、运镜、图生视频等）。
  2. 把「模型提供商」从 Mock 改成对应的火山真实模型。
  3. 点 保存模板（不要用「另存版本」——当前实现容易因唯一约束报 400）。
  4. 可选：在调试页选模型跑一下流式，确认能返回正常内容。
作用：新建分集时，项目模型配置经常是空的，流水线会回退到默认提示词模板上的模型。只建作品不改这里，仍可能继续走 Mock。
检查清单：分镜→LLM；文生图→文生图；运镜→LLM；视频→图生视频。四类都对上再往下走。

5 创建作品与分集

  1. 打开 作品管理 → 创建作品（相当于一部剧 / 系列）。
  2. 在作品下创建分集（一集对应一条流水线）。
  3. 填入本集主题 / 原始文案（越具体越好：人物、场景、情绪、时长目标）。
作用：作品管多集；分集才是真正跑阶段任务的地方。删旧作品只能清掉旧绑定，不能代替第 3、4 步改模型。

6 按流水线一步步出视频

进入分集画布后，按节点顺序推进（也可整段跑流水线，但出问题更难定位，建议第一次逐步来）。

6.1 文案改写

  • 做什么：把粗想法整理成可拍的剧本/旁白。
  • 作用：给后续分镜提供稳定输入；这一步差，后面全歪。

6.2 分镜脚本

  • 做什么：拆成镜头列表（画面描述、对白、顺序等）。
  • 作用：出图与视频都按镜头走。必须用真实 LLM；Mock 常吐散文导致解析失败。

6.3 文生图

  • 做什么：为每个镜头生成关键帧 / 参考图。
  • 作用：图生视频的输入。可微调提示词、替换不满意的镜头图。

6.4 运镜

  • 做什么：生成推拉摇移等镜头运动参数。
  • 作用：让成片更有电影感；用 LLM 阶段，模型需已激活。

6.5 图生视频

  • 做什么：按镜头图 + 运镜生成短视频片段。
  • 作用：最终成片素材。耗时与费用最高，确认前面镜头满意再批量跑。
成功标志：各阶段状态完成；能预览图/视频；日志里是真实厂商名（如「火山引擎 / …」），而不是 Mock LLM API。

6b 白模镜头预演（可选，V5b）

正式烧 Seedance 之前，用色块人偶先摆站位、机位、运镜，录一段便宜的参考视频，再当 reference_video 喂给图生视频——减少「提示词猜运镜」的废片。

入口：/static/ai-story-whitebox-previz.html（工作台 AI Story 页也有按钮）。不依赖 Docker 是否已启动。
  1. 调整角色 X/Z 站位与朝向；可加门板/方块等道具。
  2. 右侧选景别、画幅（短剧常用 9:16）、时长、运镜（推进/拉远/摇移等）。
  3. 点「录制预演」→ 自动下载 WebM + JSON；可选「保存到工作台目录」（integrated/ai_story/storage/video/whitebox_previz/）。
  4. 后续把该 WebM 作为 Seedance 参考视频；提示词写风格/服装即可，不必再堆运镜形容词。
首版边界：不做场景图一键重建白模，也没有骨骼演技库。先验证「空间对了再出片」这条链路。

? 常见问题

现象常见原因怎么处理
加载内置厂商失败 / 模型全空 backend 挂了（502） 工作台刷新状态；Docker 里看 backend/celery 是否 Up
分镜报 API请求失败: 404 LLM 的 API 地址只填了 Base（如 .../api/v3），缺 /chat/completions；或模型名不是你账号下的接入点 API 地址改为带 /chat/completions；「模型名」填火山控制台的 ep-...。表里大批目录名多数不能直接用
生图/生视频 404（模型不存在） 导入列表里的模型你账号未开通 停用不需要的；保留已验证的 Seedream / Seedance；以控制台实际可用模型为准
流水线解析 JSON 失败 仍在用 Mock LLM，或分镜 JSON 被截断 停用 Mock；改真实 LLM；剧本别太长 / 提高 max_tokens；可用「完整流程」重跑
新建作品仍像走 Mock 默认模板还绑着 Mock 见第 4 步；不要只删作品重建
出图/视频失败 只配了聊天 LLM 单独配文生图、图生视频 Key 与模型
提示词「另存版本」400 同阶段只能一条激活模板 用「保存模板」即可
页面 502，容器却显示 Up frontend 缓存了旧 backend IP docker compose restart frontend

推荐最短路径（想尽快出片）

  1. 服务就绪 → 登录
  2. 停用全部 Mock
  3. 确认 LLM / 文生图 / 图生视频都有激活的真实模型
  4. 克隆默认提示词集，四阶段都改绑真实模型并「保存模板」
  5. 新建作品与分集 → 逐步跑完五个阶段
