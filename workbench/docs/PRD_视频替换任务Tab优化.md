## 1. 背景与现状

### 1.1 已具备（As-Is）

- 侧栏入口：自动化 → 视频替换任务
- 按项目展示：琵琶曲 / 花火跳舞 / 花鼓灯换角
- 资产浏览：定妆照、原片、成片版本、报告、日志
- 进度模型：`POST /api/video-swap/projects/<id>/progress` + 轮询
- 目录由 `data/video_swap_projects.json` **固定登记**（非运行时随意扫盘）

### 1.2 核心问题

当前更像「素材橱窗」，还不是「任务工作台」：

| 角色 | 痛点 |
|------|------|
| 普通使用者 | 不知道推荐看哪个版本；对照片难找；失败原因看不懂；不能在页内发起/重跑；进度经常是空的 |
| 专业开发 | 项目靠手写 JSON；进度靠 Agent 自觉上报；无版本语义/基线锁定；无对照播放器；无任务幂等与错误码；日志与流水线未结构化 |

---

## 2. 目标与非目标

### 2.1 目标（Goals）

1. **3 秒内**看懂某项目「现在该看哪条成片、卡在哪一步、有没有挂」。
2. **不用翻文件夹**完成：看定妆 → 看原片 → 看成片 → 看对照 → 看报告。
3. **换角进行中**有可信进度（步骤 + 百分比 + 可读日志），失败可定位。
4. 专业侧：登记/版本/基线/报告有稳定约定，Agent 与人工共用同一套状态机。

### 2.2 非目标（Non-Goals）本期不做

- 替换方舟/Seedance 模型或自研 I2V
- 完整「一键从零创作短剧」产品化
- 多人协作权限、云端同步
- 自动过审/商用合规判定（可展示人工结论，不做自动判官）

---

## 3. 用户与场景

### 3.1 普通使用者（验收/监制）

- 打开 Tab → 选「琵琶曲」→ 直接播**推荐基线 v5**
- 想对比：左原片 / 右成片，或 v5 vs v6
- 问 Agent「再换一版」时，本页出现 loading、步骤、日志，不用问「好了没」

### 3.2 专业开发 / Agent 操作者

- 新项目 1 分钟登记进台
- 跑批脚本/Agent 自动写 progress + 产出版本元数据
- 出问题能从「步骤 + 错误码 + 日志锚点」定位，而不是翻 `batch_run.log`

## 5. 信息架构（To-Be）

```
视频替换任务
├── 项目列表（状态灯 / 推荐版本 / 最近更新）
└── 项目详情
    ├── 顶栏：状态 · 推荐基线 · 打开目录 · 设为基线
    ├── 进度卡：步骤条 · 百分比 · 当前消息 ·（失败时）错误摘要
    ├── 总览：推荐成片 CTA · 关键数字 · 固定目录
    ├── 定妆照：按角色分组灯箱
    ├── 原片：列表 + 播放
    ├── 成片版本：版本时间线（默认展开推荐）
    ├── 对照：分屏播放器（原片 vs 指定版本）
    ├── 报告：渲染 + 版本变更摘要
    └── 日志：任务事件流 + 文件日志（可切换）
```

## 6. 关键流程（进度）

沿用并**强制对齐**现有步骤枚举：

1. 准备定妆照与原片  
2. 分镜切段  
3. 上传参考视频  
4. Seedance 分段换角（需带 `i/n`）  
5. 拼轨合成  
6. 叠原片音轨  
7. 生成对照与报告  
8. 完成  

规则：

- Agent/脚本进入任一步必须 `POST progress`（至少 step + message）
- 分段生成时 `progress ≈ 30 + 50 * i/n`（示例约定，可调）
- 失败：`status=failed` + `error_code` + 人话 `message`
- 成功发布版本：写版本元数据并可选更新 `recommended_version`（默认不自动升基线）

## 10. 风险与依赖

- **进度真实性**：UI 再好看，不上报等于假进度 → 必须把契约写进 Agent/脚本模板  
- **大视频播放**：依赖浏览器 + `send_file` Range；对照同步播对性能敏感  
- **目录固定 vs 灵活**：向导可以「创建固定骨架目录」，避免扫无关盘符  
- **误触重跑**：P2 触发类能力必须二次确认 + 默认 dry-run

## 11. 建议决策（评审时拍板）

3. 基线变更是否需要写审计日志（谁、何时、从哪版改到哪版）？
