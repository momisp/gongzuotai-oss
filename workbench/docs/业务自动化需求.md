# 业务自动化 · 长期需求文档

> 版本：v0.2 · 更新：2026-07-28  
> 入口：工作台首页 → **业务自动化** →「需求文档」  
> 性质：长期演进模块，功能点可逐步叠加，本文档为需求基线。

---

## 1. 背景与目标

我是游戏相关业务（OA / 商务 / 会长 / 总后台 / 游戏 SDK）的测试工程师。  
本模块挂在个人工作台，目标不是再造一套 IDE，而是：

1. **在工作台内整合**接口自动化与图形自动化的执行与结果查看  
2. **新业务可拆成独立模块**，既可单测，也可挂进整条业务线  
3. **全流程可视**：节点可截图留档；需要时支持手动点选走流程  
4. **桌面精灵（简易版）**：熟悉业务线，对话快速答业务问题（可做成 Skill）

开源选型页（Midscene / Maestro 等）仅作参考；**落地工具以我实际会用的为准**：

| 类型 | 工具 | 现状 |
|------|------|------|
| 接口自动化 | **Apifox** | 计划用其跑通一条业务线（尚未开始） |
| 浏览器图形自动化 | **Playwright** | 复用「测试点生成」产出的 `.spec.ts`，工作台可直接执行 |
| 软件图形自动化 | **Airtest IDE** | 用于桌面软件、游戏客户端和移动端 |
| 编排与展示 | **本工作台** | 要做「不用打开 Apifox / Airtest IDE 也能看、能跑、能归档」 |

### 2.3 主流程节点（示例）

| 归属 | 节点 |
|------|------|
| PC OA | 上架游戏、新增商务 |

```text
上架游戏 → 商务拉新 → 会长申请/分享 → 玩家注册归属 → 充值 → 分佣核对
```

## 3. 核心能力需求（图二 · 业务部分）

### 3.1 全流程自动化（可视 + 截图留档）

- 主链路可按节点执行（接口步骤 / 图形步骤混排）  
- **每个节点**产出截图或等价证据，统一归档，便于复盘与提 bug  
- 工作台内可浏览节点状态、截图、日志（不必跳到 Apifox / Airtest）

### 3.2 可手动点击走流程

- 支持「半自动」：某节点暂停，人工在真机/浏览器点完后继续  
- 适合验证期、不稳定页面、或尚未脚本化的步骤  

### 3.3 模块化（新业务包装）

- **新游戏业务 = 一个模块**  
  - 可 **单独运行**（只测该业务）  
  - 可 **挂入主业务线**（与上架→充值等串联）  
- 模块契约建议包含：输入参数、输出上下文、依赖节点、证据目录、类型（api / ui / hybrid）

```text
[模块] 新增会长     ──┐
[模块] 分享链接     ──┼──→ [主流程] 跨端主链路
[模块] 玩家充值分佣 ──┘
         ↑
    也可单独点「只跑本模块」
```

## 4. 工作台要做的「整合层」（重点）

> 接口在 Apifox 里配、图形在 Airtest 里录——这是制作侧。  
> **工作台侧**负责编排、触发、看结果，减少来回切 IDE。

### 4.1 接口自动化整合（Apifox）

**期望（长期）：**

- 在工作台登记：业务线、环境、Apifox 项目/场景/集合标识、账号变量  
- 一键触发：调用 Apifox CLI / 开放 API / 导出的可执行包（具体方式后续选型）  
- 回写：通过/失败、断言摘要、请求响应摘要、耗时  
- 与模块绑定：例如「商务新增会长」模块 = 一组 Apifox 场景  

**现阶段：** 先在需求与模块表里占位；等我把 Apifox 第一条线跑通后再接触发器。

### 4.2 图形自动化整合（Playwright + Airtest）

按被测对象分流，避免用图像识别硬测结构稳定的网页：

- **浏览器网页**：走 Playwright，直接复用测试点中的 `playwrightSpec`；工作台负责同步模块、无头执行、查看 HTML 报告与 Trace。
- **桌面软件 / 游戏客户端 / 移动端**：走 Airtest；登记 `.air` 脚本路径、设备串和启动包名，由工作台调用 Airtest CLI。
- 两种引擎统一回收：通过/失败、控制台日志、报告或截图证据，展示在同一模块执行区。
- Airtest 与现有 **ADB / iOS 装包、截图交换目录** 对齐，证据落同一归档根目录。

**现阶段：** Playwright 模块可从测试点记录直接同步并执行；Airtest 脚本仍在 Airtest IDE 录制，工作台已提供模块登记与 CLI 执行入口。

### 4.3 统一编排壳（工作台自研）

无论引擎是 Apifox 还是 Airtest，对工作台都是：

```text
业务线 → 模块列表 → 节点（api|playwright|airtest|manual）→ 运行 / 暂停 / 续跑 → 截图与日志归档
```

差异化价值在编排壳，不在重复造 Apifox/Airtest。

## 5. 桌面精灵（图二 · 一）

### 5.1 定位

- 本质：**可通过对话驱使帮忙干活的 AI**  
- 外观：可后续套桌宠形象（已有桌宠可改）  
- **本阶段先做「业务向导」简易版**，不强求形象与干活全开

### 5.2 简易版能力（先做）

- 熟悉游戏业务线（角色 / 平台 / 流程 / 分佣关系）  
- 问到业务相关问题能 **快速、准确回答**（基于本文档 + 业务知识库）  
- 可选：回答时引用「属于哪条业务线 / 哪个模块」，方便跳到自动化页  

### 5.3 与「生成测试点」对齐的 Skill 方案

建议做成独立 Skill（类似敏捷模拟平台的 `standalone-qa`）：

| 项 | 说明 |
|----|------|
| 名称建议 | `game-biz-sprite`（游戏业务精灵） |
| 职责 | 业务答疑、流程说明、模块该测什么、和主链路怎么挂 |
| 输入 | 用户自然语言问题 |
| 知识源 | 本需求文档 + `auto_qa_plans.json` 业务线 + 后续模块清单 |
| 不做（首版） | 直接改生产数据、无人值守乱跑全链路 |

Skill 草稿路径（随仓库维护）：

`workbench/skills/game-biz-sprite/SKILL.md`

后续桌宠 UI 只做「壳」，对话大脑优先走该 Skill。

## 6. 分阶段落地（可慢慢优化）

| 阶段 | 内容 | 状态 |
|------|------|------|
| P0 | 工作台入口 + 方案展示 + **本需求文档可打开** | 进行中 |
| P1 | 模块元数据模型；Playwright 测试点同步与执行；Airtest 模块登记与执行 | 已实现首版 |
| P2 | 业务精灵：页内问答、模块推荐/确认执行、悬浮桌面窗口 | 已实现首版 |
| P3 | 接入一条 Apifox 接口线（触发 + 结果回写） | 依赖我先在 Apifox 配好 |
| P4 | 接入一条 Airtest 图形脚本（触发 + 截图回收） | Runner 已接，等待实际 `.air` 脚本 |
| P5 | 手动节点、主链路编排、新业务模块模板 | 持续优化 |
| P6 | 桌宠形象包装、对话驱动更多干活 | 已完成悬浮壳，形象可继续优化 |

原则：**先文档与契约，再 runner；制作仍用 Apifox / Airtest，工作台负责整合体验。**

## 8. 验收直觉（给未来的自己）

做到下面几条，这一版需求就算「主路径成立」：

1. 打开工作台 → 业务自动化 → 能随时看本文档  
2. 新增一个业务模块配置后，能「只跑它」也能「挂进主链路」  
3. 接口步骤结果、图形步骤截图，都能在工作台同一条时间线里看到  
4. 问精灵「会长分享链接之后玩家怎么归属？」能答对并对应到模块
