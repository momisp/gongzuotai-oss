## 0. 定位一句话

> **不是只做一张监控大屏，也不是做成 Allure TestOps**，而是工作台里的 **业务自动化总控门面**：能编目录、能排队跑、能看步骤进度、能看业务参数与证据、能重试与告警；总览形态借鉴 996 出包石板，能力按「够用的测试平台」补齐，**通用 TMS / 云真机 / 并行网格外接、不自研重造**。

```text
996 出包石板          →  本面板（自动化平台）
出包任务队列/Worker   →  自动化 Run 队列（单槽串行）
当前打包阶段          →  当前 Pipeline 步骤（SDK/表单/SQL…）
产出 exe / OSS        →  报告 HTML、日志、SQL 断言结果、关键业务 id
图形失败步骤图        →  Playwright 截图 / Trace（优化项）/ Airtest 步骤图 / 表单失败脱敏文案

市面 TestOps（Allure 等） → 用例库·趋势·多租户·缺陷治理（我们只取「通知+提单+热点」最小集）
市面 CI Dashboard（Currents 等） → Trace/Flaky/分片（我们本机单槽；失败 Trace 作 P1）
```

### 0.1 赛道结论（来自差距分析）

| 我们强 | 市面强、我们弱 | 策略 |
|--------|----------------|------|
| 钱链路混合编排（SDK+表单+SQL+PW） | 用例 TMS / 并行 Grid / 多租户 | **保持业务深度**，不扩成通用测管 |
| wired/stub 不假绿、打款门禁 | Trace/视频、Flaky 聚类 | **补工程化最小集**（见 §15） |
| 中文业务参数（游戏/会长/充提） | CI 双向、企业权限 | 通知+一键提单优先；鉴权按需 |

## 1. 背景与问题

### 1.1 工作台现状

- 入口：主流程台（弹窗）、角色台、造数脚本、模块卡片（PW/Airtest）、业务精灵  
- **自动化控制面板已上线**：总览 / 任务 / 流水线 / 设置（定时、Token）；钱链路档 A/B 与一键主链可跑  
- 钱链路为 **混合自动化**（SDK + 表单 HTTP + SQL + PW）；S7～S11 已接线；打款需 `enablePayout`  
- 相对市面平台的主要缺口（详见差距分析）：失败热点聚合、Webhook 通知、失败一键提单、PW Trace、自动重试/启动恢复、Apifox 变量桥、第 2～3 条业务链

### 1.3 要解决

1. 一眼看到自动化 **跑到哪、今天成几条、哪步总挂**（「哪步总挂」需失败热点，见 §15.1）  
2. 从业务自动化 **新开页**进入（对齐角色台）  
3. 具备自动化平台该有的能力清单（§3），缺的先脚手架  
4. 钱链路档 A / 档 B / 一键主链真跑；wired/stub 诚实；**流水核验不接入**  
5. 失败可 **通知 + 留证 + 可选提单**，不必跳进多个子系统翻日志

## 2. 目标与非目标

### 2.1 目标

| 优先级 | 目标 |
|--------|------|
| ✅ 已落地 | 入口 + 独立页；总览（排队/当前/指标/吞吐/运行情况/风险日历）；流水线分页目录 |
| ✅ 已落地 | 主链步骤条；档 A / 档 B / 一键主链；业务参数展示；S0 可自动申请游戏 |
| ✅ 已落地 | 任务列表 + 详情（日志尾 / 报告 / 业务 id / 报文 / PW 截图）；定时入队；设置 Token |
| **P0 优化** | 失败热点聚合；企微/飞书 Webhook；证据目录约定固化；失败一键提单（禅道/产品系统） |
| **P1 优化** | PW Trace on failure；自动重试≤3 + 启动恢复；Apifox variables 桥；第 2～3 条 Pipeline |
| **P2 优化** | 场景登记表；轻鉴权/审计；报告占用清理；深色主题；批量重试 |

### 2.2 非目标（持续有效）

- 不重做 Apifox / Playwright / Airtest 编辑器  
- 不接入财务流水核验  
- 不默认无人值守真打款（须 `enablePayout`）  
- 不替代主流程台细步操作（面板是总控门面）  
- **不做**完整企业级 TMS / 用例库产品（轻量登记即可）  
- **不做**自建 Selenium Grid / 云真机矩阵（外接现有设备农场即可）  
- **不做**多机集群调度大屏；本机保持 **单槽串行**（并行交给 CI/云）

## 5. 入口与信息架构

### 5.1 入口（图二）

- 页头按钮 **「自动化控制面板」**（primary）  
- 可选入口卡（与角色台并列）  
- `window.open("/auto-control", "_blank", "noopener")`

### 5.2 路由与文件

| 项 | 建议 |
|----|------|
| 路由 | `GET /auto-control` |
| 模板 | `workbench/templates/auto_control.html` |
| 前端 | `static/auto_control.js` + `auto_control.css` |
| API | `/api/auto-control/*` |
| 配置 | `data/auto_control_pipelines.json` |
| 运行 | `data/auto_control_runs/`（每 run 一目录或 JSONL） |

### 5.3 页内 Tab（对齐 996：总览 + 任务，并加平台向 Tab）

| Tab | 内容 | 来源 |
|-----|------|------|
| **总览** | 一天时间线（已启用定时的流水线横排不换行）、点中后才显示该条步骤和右侧业务参数；其下仍有排队、当前执行、指标、吞吐、风险 | 996 总览 + 本平台增量 |
| **任务** | 列表筛选/搜索/分页、重试、详情抽屉 | 996 任务页 |
| **流水线** | 目录列表（分页）+ 详情弹窗（步骤、接口、wired/stub、文档链、Profile） | **平台必备（996 无）** |
| **环境** | target、变量、Health、会话状态、打款开关 | **平台必备** |
| **模块**（可 P1） | 聚合 PW/Airtest/Apifox 登记，快捷跑 | 📎 聚合 |

首版可先做 **总览 + 任务 + 流水线**；环境可做总览顶栏折叠。

### 5.4 流水线 Tab

- 列表一行一条自动化流程，下一行是这条的定时（启用、执行时间、平台；主链另有范围）。默认按创建时间。点「按执行时间」后从早到晚排，1 点的在 2 点前面，没设时间的在最后。
- 当前可跑的是「玩家充值 → 会长提现」（`money_recharge_to_withdraw`）。金额相关另有 6 条占位：平台币回收/支付、绑币回收/充值、龙翔币支付、龙翔币回收。绑币充值不放开已写进代码的支付方式；龙翔币回收还没做，先排支付。占位只进总览时间线，到点不入队，也没有「跑一次」。
- 列：名称、标识、步骤数、未接线数、操作。档位先不出现在列表和详情里。
- **详情**打开弹窗，才展示该条的步骤卡片：步骤号、标题、执行方式、接线状态，以及该步接口（方法 / 名称 / 路径）。S4 含注册、登录、实名、上传角色、获取支付方式、提交支付。
- 分页：上一页 / 页码 / 下一页 / 跳转 / 每页 10·20·50。只有一条时仍显示分页，停在第 1 页。
- 弹窗可点遮罩、关闭或 Esc 退出。

## 6. 界面需求（总览 · 映射 996）

### 6.1 顶栏

服务状态 · 本机时间 · 告警条（红）· 轮询间隔 · 刷新 · 回业务自动化  

告警示例：`3780 未就绪` / `APIFOX_TOKEN 未配置` / `会长会话缺失` / `NTP 或时钟异常（若可检）`

### 6.2 排队优先级（左）

- queued 列表：pipeline 名、平台、入队时间、来源  
- 空态：「暂无排队任务」  
- 系统事件：「启动恢复 n 条 / 僵尸标失败」（P1）

### 6.3 当前执行（中）

| 状态 | 展示 |
|------|------|
| 空闲 | 「空闲 — 等待新任务」 |
| 运行中 | 名、当前 stepId/标题、引擎徽章、已用时、k/n |
| 失败停 | 错误摘要 + 打开日志 / 重试本步 |

主按钮：**一键跑主链**（B+打款） | **档 A · 至分佣** | **档 B · 至提现** | **停止**  
（可选次要：**仅 Apifox 充值**）

阶段文案映射（对标 996 downloading/running/uploading）：

| 内部 | 展示 |
|------|------|
| sdk / apifox | 玩家 SDK / 接口场景 |
| callback | 支付回调模拟 |
| sql_assert | SQL 断言 |
| form_admin / form_guild | 总后台/会长表单 |
| pw_admin | Playwright·总后台（可带截图） |
| stub | 待接线（停） |

### 6.3.1 本次业务参数（已落地）

总览卡片 + 任务列摘要 + 详情抽屉：游戏、会长、充值/提现金额、玩家账号、订单号、分佣、登录账号（密码不落明文）。随步骤回填。

### 6.4 指标卡

今日成功 · 今日失败 · 排队中 · 进行中(0/1) · （可选）最近耗时 · stub 未接线数  

（不做 996 的本地包数/缓存 MB，除非二期加「报告占用」。）

**P0 增量**：增加「近 7 日失败热点」入口（Top 步骤 / Top 错误指纹），点击跳任务筛选。

### 6.5 自动化吞吐

近 24h 按小时成败比例条（绿为成功占比、红为失败占比，当小时有结果则铺满该小时轨道）。空小时保持灰色。数字仍为 `成功/失败`。

### 6.6 运行情况（对标「打包情况」）

当日 / 本周 / 本月：成功、失败、成功率条；当日含进行中、排队。  
点击数字 → 任务 Tab + 筛选。  
口径：`finishedAt` 优先；本周周一至今日。

### 6.7 风险日历 · 近 7 日失败

## 8. 数据与 Pipeline 模型

### 8.1 首条 Pipeline：`money_recharge_to_withdraw`

| stepId | 标题 | 引擎 | 首版 |
|--------|------|------|------|
| S0 | 种子会长就绪 | 配置/SQL | wired |
| S1～S3 | 造数 F1～F5 | biz_flow | 默认 skip |
| S4 | 玩家注册～下单 | SDK | wired；清单含 access_key / 注册 / 登录 / 实名 / 角色 / 支付方式 / 下单。登录、获取支付方式在注册已带回 token 时标「未单独请求」 |
| S5 | 模拟回调 | HTTP :3780 | wired |
| S6 | 分佣断言 | SQL | wired |
| S7 | 渠道结算 | Playwright 总后台 | wired |
| S8 | 会长确认→可提现 | 会长表单 | wired |
| S9 | 会长提现 | 会长表单 | wired |
| S10 | 收益提现-通过 | Playwright 总后台 | wired |
| S11 | 打款 | Playwright 总后台 | wired；默认需 `enablePayout` 才打款。分支断言：本地 14:00–20:00（不含 20:00）内必须打款成功；时段外返回「只允许下午14点-20点进行打款操作」算通过，其它失败仍失败 |

档 A = S0+S4～S6；档 B = A+S7～S11。打款只在勾选 `enablePayout`（一键主链默认勾上）时执行。

### 8.2 API

| Method | Path | 说明 |
|--------|------|------|
| GET | `/api/auto-control/health` | 扩展健康（对标 996 `/health`） |
| GET | `/api/auto-control/overview` | summary：排队、当前、stats、charts、pipeline 最近态 |
| GET | `/api/auto-control/pipelines` | 流水线目录；步骤带接口清单，供列表与详情弹窗 |
| GET / PUT | `/api/auto-control/schedule` | 定时：enabled、time、profile、target、enablePayout |
| GET | `/api/auto-control/runs` | 列表；status/q/day/limit/offset |
| GET | `/api/auto-control/runs/<id>` | 详情 + logTail + steps；接口可带本次请求/响应 |
| GET | `/api/auto-control/runs/<id>/log` | 下载完整日志 |
| GET | `/api/auto-control/runs/<id>/report` | 自包含测试报告（打开即按最新模板重生成） |
| GET | `/api/auto-control/runs/<id>/shots/<path>` | 步骤截图 |
| GET / PUT | `/api/auto-control/settings` | Apifox Token、Webhook（不明文回传密钥） |
| GET | `/api/auto-control/hotspots` | **P0** 失败热点：`{ days, items:[{stepId, fingerprint, count, sampleError, lastAt}] }` |
| POST | `/api/auto-control/runs` | 入队 `{ pipelineId, profile, target, options }` |
| POST | `/api/auto-control/runs/<id>/cancel` | 停止 |
| POST | `/api/auto-control/runs/<id>/retry` | 人工重试 |
| POST | `/api/auto-control/runs/<id>/steps/<stepId>/retry` | 单步 |
| POST | `/api/auto-control/runs/<id>/ticket` | **P0** 一键提单（body: `{ system: zentao\|product, ... }`） |

响应风格可与工作台现有 `{ ok, ... }` 一致（不必强行 996 的 `code:0`）。

定时由工作台进程内约 30 秒检查一次。当天只触发一次；当时已有任务则稍后重试，超过预定时间 6 小时不再补跑。

接口原文按跑次落在 `exchanges.json`，任务总表 `auto_control_runs.json` 不放正文，避免每次拉列表都把报文读进内存。

## 15. 优化路线（对标差距分析 · 不改赛道）

> 详细对比见 `差距分析-自动化控制面板vs市面平台.md`。本节写入 **可开发的需求条目**，供排期与验收。

### 15.1 P0（约 1～2 周 · 性价比最高）

#### 15.1.1 失败热点聚合

| 项 | 说明 |
|----|------|
| 目的 | 回答「哪步总挂」，补齐风险日历「按日」之外的「按步骤/错误」维度 |
| 规则 | `fingerprint = hash(stepId + normalize(error))`；`normalize` 去掉 UUID/订单号/纯数字 id，保留文案骨架 |
| 展示 | 总览卡片「近 7 日热点」Top 5～10；点击 → 任务 Tab 带 `q` 或 `stepId` 筛选 |
| API | `GET /api/auto-control/hotspots?days=7` |

#### 15.1.2 Webhook 通知

| 项 | 说明 |
|----|------|
| 触发 | run `failed` / 步骤 `stub` 停止；（可选）`passed` |
| 渠道 | 企微或飞书机器人 URL（设置页配置，不明文回传完整 URL 时可掩码） |
| 内容 | pipeline 名、档位、平台、runId、失败步骤、error 摘要、报告链接、关键业务 id |
| 降噪 | 同一 fingerprint 15 分钟内不重复推（可配） |

#### 15.1.3 证据包目录约定（固化）

```text
data/auto_control_runs/<runId>/
  run.log
  report.html
  exchanges.json          # 可选，玩家侧报文
  shots/<stepId>/*.png    # PW 步骤
  trace/<stepId>.zip      # P1，失败时
```

报告与详情若缺 `shots` 且引擎为 `pw_*`，提示「本步无截图」。

#### 15.1.4 失败一键提单

| 项 | 说明 |
|----|------|
| 入口 | 任务详情抽屉按钮 |
| 目标 | 禅道 Bug 和/或 产品系统缺陷（复用工作台已有能力） |
| 正文模板 | 标题：`[自动] {pipeline} {stepId} {error骨架}`；正文含步骤时间线摘要、业务参数、报告 URL、runId |
| 指派 | 若步骤/备注带开发者名则沿用 XMind→禅道规则；否则默认前端负责人（见工作台规则） |
