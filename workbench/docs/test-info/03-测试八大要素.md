# 测试八大要素（实用版）

经典教材常讲「测试的基本原则 / 要素」。落到日常可记这 **八条**：

> **别和「测试用例八要素」搞混**  
> - **本文**：测试工作应遵循的 **原则**（怎么规划、怎么取舍）  
> - **用例八要素**：写一条用例要具备的 **字段**（编号、标题、步骤、预期等）→ 见 `10-测试用例八要素.md`

## 1. 测试显示缺陷存在，不能证明没有缺陷

测通 ≠ 无 bug。结论要写清**覆盖了什么、没覆盖什么**。

## 2. 穷尽测试不可能

用等价类、边界值、风险优先级裁剪；把精力放在高损场景。

## 3. 早期测试

需求/原型阶段就开始测点与疑问清单，别等「包出来再说」。

## 4. 缺陷集群

缺陷常扎堆在少数模块。找到脏区后加深测，别平均用力。

## 5. 杀虫剂悖论

同一套用例反复跑，抓虫能力下降。要轮换数据、路径、环境，定期改用例。

## 6. 测试依赖上下文

游戏、支付、后台、小程序策略不同；别套错清单。

## 7. 无错误谬误

「零 bug」也可能产品不可用（体验差、性能差、需求错）。要对照验收标准。

## 8. 测试活动应与风险相关

风险高（资金、账号、权限、数据一致性）→ 测得更深、更早、更频。
