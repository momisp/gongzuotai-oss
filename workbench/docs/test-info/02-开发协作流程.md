# 开发协作流程（测试视角）

测试不是「等包再测」，而是嵌入研发节奏。

## 1. 协作泳道（简化）

```
产品：需求/原型
  ↓
研发：设计/开发/自测
  ↓（提测）
测试：冒烟 → 深测 → 回归
  ↓
发布：发版检查 → 观察
```

## 2. 测试需要研发配合的输入

| 输入 | 用途 |
|------|------|
| 变更说明 / MR 描述 | 定回归范围 |
| 接口文档 / Apifox | 接口与数据校验 |
| 测试环境账号与权限 | 角色场景 |
| 配置开关 / 灰度策略 | 场景覆盖 |
| 已知问题清单 | 避免重复提单 |

## 3. 缺陷协作约定（建议）

- **标题**：模块 + 现象 + 影响
- **环境**：包体/分支/账号/设备
- **步骤**：可复现；附截图或日志
- **期望 vs 实际**：写清
- **严重级别**：按业务影响，不按「难不难修」

## 4. 提测质量（减少空转）

研发自测至少覆盖：

- 主路径可走通
- 明显崩溃 / 白屏 / 接口 500 已处理
- 与本次改动相关的旧功能抽测

## 5. 常见卡点

- 环境漂移（配置、域名、证书）
- 账号权限不全
- 依赖联调未就绪却提测
- 变更范围说不清 → 回归打盲

卡点优先进 **QA 问题集**，下次评审直接复用。
