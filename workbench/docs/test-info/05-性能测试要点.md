# 性能测试要点

## 目标

在约定负载下，系统是否**够快、够稳、资源可接受**。

## 常见类型

| 类型 | 问什么 |
|------|--------|
| 负载 | 目标并发下响应与错误率 |
| 压力 | 压到哪里开始崩、能否恢复 |
| 稳定性 | 长时间跑是否泄露/漂移 |
| 容量 | 再加多少量需要扩容 |
| 峰值 / 毛刺 | 瞬时流量冲击 |

## 开工前要对齐

1. **场景**：哪个接口/页面，业务占比
2. **指标**：P95/P99、错误率、TPS、资源水位
3. **环境**：尽量接近生产（或明确差异）
4. **数据**：账号池、订单量、缓存是否预热
5. **观察**：应用日志、DB 慢查询、机器 CPU/内存/连接数

## 最小执行步骤

1. 单接口基线（1 用户）  
2. 阶梯加压到目标并发  
3. 稳住观察 10～30 分钟  
4. 回收：对比基线，定位瓶颈（应用 / DB / 中间件 / 前端）

## 结果怎么写

- 结论：**达标 / 有条件达标 / 不达标**
- 附：压测曲线、错误样例、慢 SQL、资源图
- 给出**可执行建议**（限流、索引、缓存、扩容）

工作台「压测工具」可做执行侧入口；本页管「测什么、怎么判」。
