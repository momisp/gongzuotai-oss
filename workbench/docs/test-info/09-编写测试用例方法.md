# 编写测试用例的方法

把需求/原型变成**可执行、可判定**的用例。核心不是堆数量，而是用对技法、写清预期。

## 用例最小结构

| 字段 | 写什么 |
|------|--------|
| 标题 | 一句话说清「测什么 + 什么条件」 |
| 前置 | 账号/数据/环境/已处于某状态 |
| 步骤 | 可照做的操作（1、2、3…） |
| 数据 | 输入值、文件、接口参数 |
| 预期 | **可观察**结果（文案、状态、库表、接口码） |
| 优先级 | P0 冒烟 / P1 主功能 / P2 次要 / P3 体验 |

完整「用例八要素」（含编号、所属模块等）见：`10-测试用例八要素.md`。

坏预期：「正常」「没问题」。好预期：「提示“金额须 ≥1”且不提交；列表不新增」。

---

## 1. 等价类划分（Equivalence Partitioning）

**思路**：把输入分成几类，同类行为应一致 → 每类抽 1～2 个代表值即可。

| 类型 | 含义 | 例：年龄 1～120 |
|------|------|----------------|
| 有效等价类 | 应接受 | 18、60 |
| 无效等价类 | 应拒绝 | 0、121、空、字母、小数 |

**做法**

1. 列出约束（范围、格式、必填、枚举）
2. 划有效 / 无效类（无效常比有效多）
3. 每类至少 1 条用例；高风险类可多抽

**适合**：输入域大、规则清晰（手机号、金额、枚举下拉）。

---

## 2. 边界值分析（Boundary Value Analysis）

**思路**：缺陷常出在边界上；边界及紧邻点优先测。

对区间 `[min, max]`（含端点）常用取值：

| 点 | 值 | 期望 |
|----|-----|------|
| 下越界 | min−1 | 拒绝 |
| 下边界 | min | 接受 |
| 下邻内 | min+1 | 接受 |
| 上邻内 | max−1 | 接受 |
| 上边界 | max | 接受 |
| 上越界 | max+1 | 拒绝 |

**例**：密码长度 6～16

- 5、6、7、15、16、17
- 再补：空、全空格、中文、特殊字符（若规则有）

**还要盯这些「边界」**

- 长度：0 / 1 / 上限 / 上限+1
- 数值：0、负数、最大 int、小数位
- 日期：当天、跨月、闰年 2/29、时区切日
- 列表：0 条、1 条、刚好一页、一页+1
- 文件：0KB、刚好上限、超限、空文件、错误后缀
- 金额：0.00、0.01、最大可付、超额 0.01

**口诀**：边界值 = 等价类的「放大镜」，两者通常一起用。

---

## 3. 判定表（Decision Table）

**思路**：多个条件组合决定不同结果时，用表穷举（或按规则合并）。

**例**：优惠券（简化）

| 条件\规则 | R1 | R2 | R3 | R4 |
|-----------|----|----|----|----|
| 已登录 | Y | Y | N | Y |
| 券未过期 | Y | N | - | Y |
| 满足门槛 | Y | Y | - | N |
| **结果** | 可用 | 提示过期 | 引导登录 | 提示未满门槛 |

每列 → 至少 1 条用例。条件多时先找**互斥/依赖**再删不可能组合。

**适合**：权限 × 状态、活动规则、审核分支。

---

## 4. 因果图 / 正交（组合爆炸时）

- **因果图**：条件多且有约束，先画因果再转判定表。
- **正交表 / 成对（Pairwise）**：参数很多（浏览器×系统×开关）时，保证两两组合覆盖，而不是全排列。

日常可先：主路径全覆盖 + 高风险两两组合。

---

## 5. 状态迁移（State Transition）

**思路**：对象有明确状态机时，测「合法迁移」和「非法迁移」。

**例**：订单

```
待支付 → 已支付 → 已发货 → 已完成
   ↓         ↓
 已取消    退款中 → 已退款
```

要写的用例：

- 每条合法箭头走一遍
- 非法：已完成再支付、已取消再发货 → 应失败且状态不变
- 同一状态重复操作（重复支付、重复取消）

**适合**：订单、审核流、会话/登录态、工单。

---

## 6. 场景法 / 用例路径

**思路**：按真实用户故事串主路径 + 分支。

1. 基本流（happy path）
2. 备选流（改地址、用券、返回修改）
3. 异常流（超时、库存不足、支付失败）

每条流写成用例或「场景用例组」。与工作台「业务场景测试点」一致。

---

## 7. 错误猜测（Error Guessing）

经验向补洞，常见脏路径：

- 连点提交、重复请求
- 弱网 / 断网 / 杀进程再进
- 复制粘贴空格、emoji、超长粘贴
- 并发两人抢同一库存/同一单
- 权限越权（改别人 ID、直打接口）
- 后退、刷新、多标签

有历史 bug 的模块优先加深。

---

## 怎么选技法（速查）

| 你面对的是… | 优先用 |
|-------------|--------|
| 单个输入框规则 | 等价类 + 边界值 |
| 多条件出不同结果 | 判定表 |
| 有状态流转 | 状态迁移 |
| 完整业务故事 | 场景法 |
| 参数组合爆炸 | 成对 / 正交 |
| 老模块、脏区 | 错误猜测 + 边界加强 |

推荐组合：**场景骨架 → 输入用等价类/边界 → 规则用判定表 → 状态流补迁移 → 经验补猜测**。

## 写法示例（边界值）

**标题**：充值金额边界_最小值 0.01 可提交  

**前置**：已登录；账户可充值  

**步骤**  
1. 打开充值页  
2. 金额输入 `0.01`  
3. 点击确认  

**预期**：进入支付；订单金额为 0.01；成功后余额 +0.01  

---

**标题**：充值金额边界_0 不可提交  

**步骤**：金额输入 `0` → 确认  

**预期**：按钮不可点或提示「金额须大于 0」；无订单；余额不变  

---

## 自检清单（交用例前）

- [ ] 每条都有**可判定**预期（不是“正常”）
- [ ] 有效 / 无效 / 边界都覆盖到了关键规则
- [ ] P0 能单独拉成冒烟清单
- [ ] 权限、空态、失败提示有用例
- [ ] 和需求/原型有追溯（测点或需求编号）
- [ ] 无大量重复（同等价类别堆 10 条）
