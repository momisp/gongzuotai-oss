# 测试流程（提测 → 发版）

> 可按你们团队节奏裁剪；核心是**闸门清晰、证据可回看**。  
> 工作台「今日工作台」右侧面板同步展示本流程；项目产出建议落在  
> `F:\OA-test\项目安装包\<项目目录>\测试过程产出`。

## 1. 阶段总览

```
需求评审 → 测试点/用例设计 → 提测准入 → 冒烟
  → 功能/场景测试 →（按需）性能/安全 → 回归 → 发版验收 → 线上观察
```

## 2. 各阶段要点与交付物

| 阶段 | 测试人员要做什么 | 必须交付物 |
|------|------------------|------------|
| **需求评审** | 确认验收可测、范围边界、角色权限与异常 | 可测验收标准；范围边界（含不测项）；角色/权限/异常清单；接口/配置/第三方回调列表 |
| **测试点/用例设计** | 页面框架 → 业务场景 → 页面功能；冒烟单独拎出 | 三类测试点（XMind/MD）；冒烟门禁清单；专项点（按需）；用例已导入产品系统套件 |
| **提测准入（DoR）** | 核对包/环境/账号与变更范围 | 提测说明；环境与账号就绪确认；安装包或访问地址可用证明；开发自测/已知阻塞清单 |
| **冒烟测试** | 主链路通不通（断了打回） | **冒烟测试报告**（范围/时间/环境/结论）；执行结果；阻断 Bug；过程截图（可选） |
| **功能/场景测试** | 业务正确性与分支 | 执行进度与结果；缺陷清单；阶段测试报告；待核实项跟踪表 |
| **回归测试** | 改动面 + 历史高危 | 回归范围说明；回归结果；未关闭 P0/P1 与豁免说明 |
| **发版验收（DoD）** | P0/P1 清零或书面豁免；关键场景再跑 | 发版验收清单；发版测试报告；回滚方案 / 观察指标 |
| **线上观察** | 发版后 24h 看监控/客诉 | 巡检记录；异常跟进；问题复盘（按需） |

### 需求评审

- 验收标准可测（Given/When/Then 或等价表述）
- 角色、权限、异常与边界写清
- 关联接口、配置、第三方回调列出

### 测试设计

- 先**页面框架 → 业务场景 → 页面功能**（与工作台「测试点生成」一致）
- 冒烟清单单独拎出（最短主路径）
- 风险高的模块优先（支付、登录、权限、数据一致性）

### 提测准入（DoR）

- 包体可装、环境可用、账号就绪
- 自测/冒烟通过说明或已知阻塞清单
- 变更范围（模块/接口/配置）明确

### 执行

1. **冒烟**：主链路通不通（断了就打回）
2. **功能 / 场景**：业务正确性与分支
3. **回归**：改动面 + 历史高危
4. **非功能**（按需）：性能、安全、兼容

### 退出与发版（DoD）

- P0/P1 清零或有书面豁免
- 冒烟 + 关键场景再跑一轮
- 回滚方案 / 观察指标清楚

### 测试报告格式（自 1.4.6 起）

- 阶段报告须含 **附录 A · 相关接口清单**（Apifox/OpenAPI）
- 同目录落 JSON 机读清单，供后续接口自动化
- 详见：`12-测试报告模板-含接口附录.md`

## 3. 日常节奏建议

| 时机 | 动作 |
|------|------|
| 每日构建 | 冒烟 |
| 提测当日 | 冒烟 → 主功能 |
| 迭代中期 | 场景深测 + 缺陷验证 |
| 发版前 | 回归 + 发版清单 |
| 发版后 24h | 看监控/客诉/核心指标 |

## 4. 和本工作台的对应

- 今日工作台右侧「测试流程 / 项目进度」：阶段交付物 + 近期项目到哪一阶段
- 测试点生成：设计阶段产出
- 产品系统用例库：用例归档与执行
- 远程装包 / 业务自动化：执行阶段
- QA 问题集：踩坑沉淀
- 测试运维工作区：发版后巡检
