# 功能测试要点

## 目标

验证**功能是否按需求正确工作**：界面、逻辑、数据、权限、异常。

## 设计顺序（推荐）

1. **页面框架**：有哪些页/模块
2. **业务场景**：角色 × 主路径 × 分支（通过/驳回等）
3. **页面功能**：控件行为、校验、提示、状态

（与工作台「测试点生成」三步一致。）

## 常用技法

| 技法 | 何时用 |
|------|--------|
| 等价类 | 输入域大，需抽样 |
| 边界值 | 长度、金额、日期、数量 |
| 判定表 / 因果图 | 多条件组合 |
| 状态迁移 | 订单、审核、会话 |
| 错误猜测 | 经验向脏路径 |

详细写法、示例与自检见：`09-编写测试用例方法.md`。

## 必测清单（精简）

- [ ] 主路径 happy path
- [ ] 必填/格式校验与提示
- [ ] 权限：无权限不可见/不可操作
- [ ] 异常：网络失败、接口错误码、空数据
- [ ] 返回/刷新/后退不丢关键状态
- [ ] 列表：分页、筛选、排序、空态
- [ ] 与后端数据一致（抽关键字段核对）

## 和冒烟 / 场景的关系

- **冒烟**：主链路能不能用
- **功能细项**：控件与规则对不对
- **场景**：整条业务在真实条件下结果对不对

详见：`冒烟测试与场景测试区别.md`
