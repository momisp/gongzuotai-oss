## 三、第 6 点专题：生成「页面框架」时的扫描动画

### 3.1 你的想法（摘要）

1. 画面先显示**真实原型**  
2. 有一条类似**激光扫描**的标记，大致**上→下、左→右**移动  
3. 扫到例如「工作台」→ 标成框架目录项 → 加入右侧/侧边框架树  
4. 希望尽量跟**实际原型**对应；结合现有浏览器渲染  
5. 问：是不是一页页渲染？能不能渲染后加扫描标记？市面有没有类似可借鉴？

### 3.2 技术事实（对齐预期，避免「以为 AI 真在扫」）

| 事实 | 说明 |
|------|------|
| AI **不会**边看边扫图 | 当前流水线是：Playwright 渲染抓结构 → 把导航/正文文本塞进 prompt → 模型输出 Markdown 框架。模型看不到像素扫描过程。 |
| 浏览器渲染 **已有** | `fetch-prototype-rendered.mjs`：打开预览 → 进 iframe → 自动登录 → 抽侧栏树（工作台/商务管理…）。 |
| 现在 **不是**一页页翻完再给模型 | 通常是：登录页 → 登录后工作台这一屏抽导航；不会默认把每个子菜单点开截全站。 |
| 可以做到的「真」 | 在渲染阶段多拿：**整页截图 + 每个导航项的 bounding box（坐标）+ 标题文案**，按阅读序排序；前端用这些真数据播扫描动画。 |
| 树长出来可以「半真」 | 扫描阶段按 DOM 抽出的模块依次入树；随后 LLM 流式输出时，再用 SSE 把 `## 商务管理` 等标题与树上节点对齐加亮（可选）。 |

结论：**动画可以做得「看起来像在扫原型建框架」，底层必须是「渲染结果的可视化回放」，不是模型实时视线。** 对用户观感一致即可，文案上建议写「正在梳理页面结构」而不是「AI 正在用眼睛扫描」。

### 3.3 市面/开源可借鉴（不直接整包接入，借交互）

| 参考 | 链接/形态 | 可借什么 |
|------|-----------|----------|
| Playwright bounding box 叠加 | 常见写法：`locator.boundingBox()` + 绝对定位高亮框 | **扫到某模块时画框** |
| [screenshot-annotator](https://github.com/arjunkai/screenshot-annotator) | 截图前注入 DOM 标注再拍 | 标注框、编号 callout |
| Playwright screencast overlay | 官方录屏叠加层 API | 录制演示视频时的框选（我们主路径用前端叠加即可） |
| [playwright-spatial-layout-mcp](https://github.com/vola-trebla/playwright-spatial-layout-mcp) | 暴露布局几何给 Agent | 「空间结构」思路，偏工具链，不必接 MCP |
| Foveacast / UX HeatGrid 等 | 注意力热力/扫视路径 | **激光/扫视线**视觉语言；不适合当模块识别源 |

**建议：不引入重型热力模型；自研「截图 + bbox 扫描条 + 高亮框 + 框架树渐入」即可，暖色主题下用橙色激光条。**

### 3.4 三种实现档位（请你选）

#### 方案 A · 轻量过程条（最便宜）

- 主区显示步骤清单动画：打开原型 → 登录 → 识别侧栏 → 写入框架  
- **不**显示真实页面截图与激光  
- 工作量小，和「扫到工作台再入树」差距大  

#### 方案 B · 推荐：真实截图 + 激光扫描 + DOM 模块入树（对齐你的描述）

**流水线：**

1. 浏览器渲染（现有）结束后，额外产出：  
   - `scan.screenshot`（登录后工作台整页 PNG）  
   - `scan.regions[]`：`{ id, title, rect:{x,y,w,h}, order }`（侧栏/顶栏模块，按上→下、左→右排序）  
2. SSE 推给前端：`type: "qa_scan_story"`  
3. 主区播放：  
   - 先铺原型截图  
   - 橙色激光条从上往下（侧栏区域可优先竖扫）  
   - 扫到某 `rect` → 描边高亮 + toast「识别为一级模块：工作台」→ 右侧框架树追加节点  
4. 扫描播完（或并行）再跑/继续 LLM 生成完整 Markdown（补业务简介等）  
5. 最终脑图/文本仍以模型输出为准；扫描树作「识别预览」，可与终稿 diff 高亮  

**优点：** 最接近你描述；基于真实原型；不假装模型在扫。  
**成本：** 中等（渲染侧加截图+bbox；前端扫场播放器）。  
**限制：** 默认仍是「当前这一屏」；子页要扫需方案 C。

#### 方案 C · 增强：多页翻扫（更重）

- 在 B 基础上，按导航逐个点击：工作台 → 商务列表 → … 每页截一张，多段扫描  
- 或只扫侧栏展开后的叶子  
- **优点：** 「一页页渲染」观感更强  
- **缺点：** 耗时明显变长（每页数秒）、易受登录/弹窗干扰、失败率更高  

**建议首版不做 C，或做成可选「深度扫描」。**

### 3.5 与「AI 思考过程」如何衔接

| 做法 | 说明 |
|------|------|
| 不推荐 | 试图解析模型「内心」逐步对应像素（没有稳定信号） |
| 推荐 | **两段式**：① 结构扫描（真 DOM）入树；② 模型流式输出时，匹配已出现的 `## 标题` 在树上脉冲高亮 |
| 文案 | 「浏览器已打开原型并识别模块」→「正在生成框架说明」 |

### 3.6 已敲定选型（2026-08-04 · 用户确认）

| # | 选项 | 结论 |
|---|------|------|
| 1 | 档位 | **B**：真实截图 + 激光扫描 + DOM 模块入树 |
| 2 | 时机 | **B1**：先播完扫描，再调模型生成完整框架 Markdown |
| 3 | 默认范围 | **可以**：仅登录后首页侧栏（当前这一屏），不做默认多页翻扫 |
| 4 | 失败回退 | **要降级**：拿不到截图/bbox 时自动降级为方案 A 步骤条 |

**实现要点（开发备忘）：**

1. 渲染阶段产出 `screenshot` + `regions[{title, rect, order}]`，SSE：`qa_scan_story`  
2. 前端播完扫描（树渐入）后，再发起/继续框架 LLM  
3. 无截图或 regions 为空 → 步骤条（打开原型 → 登录 → 识别侧栏 → 生成框架）  
4. 方案 C（多页深扫）本轮不做，仅文档保留为后续可选项
