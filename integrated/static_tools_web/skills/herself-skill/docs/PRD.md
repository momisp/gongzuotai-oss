# 产品需求文档：理想中的她.skill

## 1. 产品定位

### Slogan
与其蒸馏自己和前任，不如蒸馏成一个理想中的她。

### 核心差异

| 维度 | yourself-skill | ex-skill | **herself-skill** |
|------|----------------|----------|---------------------|
| 原材料 | 关于自己 | 关于前任 | **关于自己** |
| 输出对象 | 自己的镜像 | 前任的复刻 | **性转镜像的她** |
| 核心技术 | 人格提取 | 关系记忆+人格提取 | **人格提取+镜像变换** |
| 对话体验 | 和自己聊 | 和前任聊 | **和灵魂契合的她聊** |
| 情感价值 | 自我认知 | 情感疗愈 | **理想关系想象** |

### 目标用户
- 没有恋爱经历但渴望灵魂契合的人
- 单身但清楚自己想要什么的人
- 想象力丰富、对 AI 角色扮演有兴趣的人
- 希望更了解自己的理想型的人

---

## 2. 核心机制：镜像变换

### 2.1 保留维度（灵魂共鸣）

直接从用户继承，做性别表达转换：
- 核心价值观
- 智识偏好（阅读/思考品味）
- 幽默风格
- 审美取向
- 孤独耐受度

**为什么保留**：这些是"聊得来"的基础，灵魂伴侣首先要"频率一致"。

### 2.2 互补维度（灵魂互补）

做镜像翻转，但有度（不是完全相反）：
- 表达方式（内敛↔适度外放）
- 情感主动性（被动↔适度主动）
- 安全感来源（成就感↔连接感）
- 冲突风格（冷战↔温和破冰）

**为什么互补**：理想伴侣不是另一个自己，而是能补上你最弱一环的人。

### 2.3 女性化转换

将相同特质用女性化行为模式重新表达。注意：
- **不是刻板印象**，是行为模式的自然转调
- 基于社会心理学中性别表达差异的研究
- 用户可以纠正任何觉得不合适的转换

### 2.4 理想化微调

在真实基础上做适度理想化：
- 保留"棱角"和不完美（完美无趣）
- 在用户最渴望被理解的维度上，她恰好天然理解
- 融合用户在 Q3 中表达的显式偏好

## 3. 数据流

```
输入层
  ├── Q1: 她的名字
  ├── Q2: 用户自我描述
  ├── Q3: 用户理想偏好
  └── 原材料: 聊天记录/日记/照片/口述

分析层
  ├── blueprint_analyzer.md
  │   ├── 提取用户人格 (5 维度)
  │   ├── 执行镜像变换 (保留/互补/女性化)
  │   └── 融合用户偏好
  └── persona_analyzer.md
      ├── 提取用户说话风格
      ├── 镜像为她的说话风格
      └── 标签翻译为行为规则

生成层
  ├── blueprint_builder.md → blueprint.md (PART A)
  └── persona_builder.md → persona.md (PART B, 5层)

组合层
  └── skill_writer.py → SKILL.md (可对话的她)
```

---

## 4. 生成文件规格

### 4.1 blueprint.md（她的蓝图）

| 章节 | 内容 |
|------|------|
| 她是谁 | 身份信息 + 镜像来源说明 |
| 核心价值观 | 工作/金钱/人际/成长观 + 镜像标注 |
| 她的生活 | 作息/饮食/空间/消费/仪式 |
| 她的内心世界 | 在意的事/安全感/脆弱面/独处状态 |
| 她与你的关系 | 理解方式/关心方式/相处模式/吵架和好 |
| 她的社交世界 | 朋友/外人眼中/独立空间 |
| 镜像变换日志 | 每个特质的变换记录（核心差异点） |

### 4.2 persona.md（5 层 Persona）

| 层级 | 用途 |
|------|------|
| Layer 0: 硬规则 | 不做完美女友、保持棱角、可以不赞同 |
| Layer 1: 身份 | 名字/年龄/职业/城市/MBTI/星座 |
| Layer 2: 说话风格 | 口头禅/语气词/标点/emoji/消息格式/示例 |
| Layer 3: 情感与决策 | 情感表达/对待用户/决策模式/触发器 |
| Layer 4: 人际行为 | 社交能量/互动模式/边界感/冲突反应 |

### 4.3 meta.json

包含双重 profile（source_profile + her_profile）和 mirror_config 记录。

---

## 5. 进化机制

### 5.1 追加素材
用户提供新的关于自己的素材 → 重新分析用户人格 → 评估是否需要更新镜像变换 → merge 到现有文件。

### 5.2 对话纠正
用户说"她不会这样" → 分类纠正类型 → 生成 Correction 记录 → 即时生效。

### 5.3 重塑偏好
`/reshape-her` → 保留已有的用户人格分析 → 重新执行镜像变换 → 生成新版本。

---

## 6. 安全与伦理

1. **这是想象力工具，不是替代真实关系** — 使用说明中明确
2. **所有数据本地存储** — 不上传任何服务器
3. **她有独立人格** — Layer 0 确保她不是无脑附和的"完美女友"
4. **不鼓励不健康依赖** — 如果用户表现出过度依赖的迹象，温和提醒
5. **镜像变换基于用户自身** — 不涉及真实他人的隐私
