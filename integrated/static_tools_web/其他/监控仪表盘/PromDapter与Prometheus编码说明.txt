  PromDapter → Prometheus 报「不是有效的 utf8」时怎么处理
═══════════════════════════════════════════════════════════

【一】为什么会出现这个错
────────────────────────────────────────────────────────────
1. Prometheus 要求指标名符合 ASCII 规则，形如：
   [a-zA-Z_:][a-zA-Z0-9_:]*
   也就是说：指标名里一般不应出现中文。

2. PromDapter 默认映射可能生成类似：
   hwi_core_core_0_倍频_x
   其中「倍频」在指标名里，容易导致解析/校验失败。

3. 错误里出现 \x80\x8d 这类字节，多为 HWiNFO 里某段说明是 GBK/系统编码，
   被当成 UTF-8 解析时就会报「不是有效的 utf8」——整次抓取失败，Grafana 就永远没有曲线。


【二】推荐做法（改映射，指标名只用英文/数字/下划线）
────────────────────────────────────────────────────────────
1. 先备份文件（复制一份到桌面）：
   C:\ProgramData\PromDapter\Prometheusmapping.yaml
   （安装目录里也可能有一份示例：C:\Program Files\PromDapter）

2. 用记事本 / VS Code 打开 Prometheusmapping.yaml，搜索：
   倍频、或其它带中文的指标名相关规则。

3. 把会生成「中文指标名」的规则改成**纯 ASCII 名**，例如：
   - 原来类似 hwi_core_core_0_倍频_x
   - 改成 hwi_core_core_0_multiplier_x 或 hwi_core_core_0_clock_ratio
   （具体改法取决于你文件里的 YAML 结构：有的用 metric_name 模板，有的用正则替换。）

4. 若一时找不到对应段：可**整段注释掉**与「Core 0 倍频」相关的映射（YAML 里用 # 注释），
   先让 Prometheus Targets 变 UP，再慢慢补英文指标名。

5. 保存后，浏览器访问（触发热载配置）：
   http://127.0.0.1:10445/metrics/reset

6. 再打开 http://127.0.0.1:10445/metrics ，确认：
   - 不再出现带中文的指标名（尤其不要有「倍频」拼在名字中间）
   - # HELP 行里没有乱码

7. 回到 Prometheus → Status → Targets，确认 promdapter（或 promdapter 任务名）为 UP。


【三】仍报错时
────────────────────────────────────────────────────────────
• 在 HWiNFO 里把对应传感器的「显示名称」改成英文，重启 HWiNFO 与 PromDapter 后再 reset。
• Windows 区域设置里开启「Beta：使用 Unicode UTF-8 提供全球语言支持」后重启（见 使用说明.txt）。
• 升级/更换 PromDapter 版本（看 GitHub Release 说明）。


【四】和 Grafana「第二步没曲线」的关系
────────────────────────────────────────────────────────────
只要 Targets 还是 DOWN，Grafana 里无论怎么查 {__name__=~"hwi.*"} 都不会有数据。
必须先让 /metrics 被 Prometheus 完整接受（UP），再在 Grafana 探索里选 hwi_ 开头的**合法指标名**。

【五】本仓库提供的自动替换脚本（在你自己电脑上执行）
────────────────────────────────────────────────────────────
同目录下「patch-Prometheusmapping.ps1」会备份 `C:\ProgramData\PromDapter\Prometheusmapping.yaml`（或 Program Files 下副本），
并把常见「带下划线的中文指标名片段」改为 ASCII。执行：
  powershell -ExecutionPolicy Bypass -File .\patch-Prometheusmapping.ps1
然后访问 http://127.0.0.1:10445/metrics/reset
