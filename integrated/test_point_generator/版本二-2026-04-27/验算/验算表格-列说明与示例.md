# 验算表格（对齐图六列）

用于手工填写或与页面 `calculator.html` 每步快照对照。

## 列定义

| 列名 | 含义 | 与计算器字段对应 |
|------|------|-------------------|
| **当前可预支额度** | 会长当前还能再预支多少（本金口径上限由额度公式卡） | 快照列 `可预支额度`（已含 min(0) 与上限裁剪） |
| **(玩家充值产生的)待结算金额** | 真充分佣尚未结入真实余额库部分 | 快照 `玩家充值待结算`（本计算器若未单独建模流水结算，可为 0，以线上为准） |
| **预支产生的待结算金额** | 预支代充分佣尚未转入预支余额库 / 尚未参与某环节的部分 | 快照 `预支待结算分佣` |
| **实际显示的提现余额** | 页面给用户看的可提现相关余额 | `计算用余额(真实库) + 预支余额库 + 预支待结算分佣`（与计算器 `显示提现余额` 一致） |
| **余额(用来计算预支的提现余额)** | 参与「可预支额度」计算的真实侧基数（图六口径） | 快照 `计算用余额(真实库)` = 真实余额库 |
| **已预支金额(待还)** | 未归还的预支本金 | `待还预支本金` |
| **白名单配置(10万)** | 可预支封顶（元） | 默认 100000，计算器可改 |

**业务公式（与说明图对齐，便于自查）：**

1. **可预支额度（未截顶前）** = 真实余额库 − 待还预支本金；结果 &lt; 0 时按 0；再与 **白名单上限** 取 min。
2. **显示提现余额** ≈ 真实余额库 + 预支余额库 + 预支待结算分佣（与图六：730 + 73 = 803 同类）。
3. **还款**：优先冲减 **预支余额库**，不足部分再消耗 **真实余额库**（体现为「已用于还款的现金分佣」增加）。

| 当前可预支额度 | 玩家充值待结算 | 预支产生待结算 | 实际显示提现余额 | 计算用余额 | 已预支(待还) | 白名单(10万) | 说明 |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---|
| 730 | 0 | 0 | (空或同左) | 730 | 0 | 100000 | 初始：真实库 730，无预支 |
| 630 | 0 | 73 | 803 | 730 | 100 | 100000 | 预支本金 100：待还 +100，待结算分佣 +73，可预支 730−100 |
| 703 | 0 | (空) | 703 | 703 | 0 | 100000 | 还清后：待结算归库，口径收敛 |
| 653 | 0 | 36.5 | 739.5 | 703 | 50 | (空) | 部分还款/再预支类场景 |

## 与业务流程对照检查项

- [ ] 仅 **真充** 路径增加 **真实余额库**；**预支代充** 路径增加 **预支侧**（待结算 / 预支库），不把预支单产生的可预支再滚雪球（以产品文档为准）。
- [ ] **可预支** 不超过白名单；还款后 **待还** 与 **额度** 同步变化。
- [ ] **还款** 扣减顺序：预支余额库优先，再动真实余额库。

## 用 `calculator.html` 复现图六第 1～2 行（分佣 73%）

1. 打开 `calculator.html`，白名单保持 **100000**，比例 **0.73**。  
2. **现金充值**：本金约 **1000**（`1000×0.73=730`），得到真实库 **730**、可预支 **730**、显示提现 **730**。  
3. **预支额度充值** 本金 **100**：待还 **100**、预支待结算分佣 **73**，可预支 **630**、显示提现 **803**（730+73）。  
4. 若要与「预支分佣已入账」状态对齐，点击 **「结算：预支待入账分佣 → 预支库」**，预支待结算并入预支库，显示提现仍为 **803**，预支库变为 **73**。
