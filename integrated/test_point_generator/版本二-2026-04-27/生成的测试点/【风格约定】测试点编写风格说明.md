# 【风格约定】测试点编写风格说明（来自图一脑图 + 原型补充）

> **用途**：后续你提供「类似结构」的原型图时，按本文档结构与方法输出测试点。  
> **来源**：图一（个人脑图风格）+ 还款记录/预支管理/白名单/新增编辑删除弹窗等原型。

---

## 一、整体形态

- **格式**：思维导图式层级树：`根模块 → 子模块/Tab → 固定四类（或扩展）→ 具体测试点`。
- **叙述**：短句、可执行；优先写能、无法、显示；界面文案、按钮名、报错句用「」括起，与原型一致。
- **与原型关系**：有独立交互的列表/表单页，习惯先写「界面与原型一致」。

### 简洁与粒度（必守）

- **「界面与原型一致」**：对应原型里**一整块版式**时，通常写**一条**即可：标题、Tab、筛搜、主按钮、表头与关键控件在同一句话里概括；**不要**在同页再写「点击某 Tab 能切换」类交互塞进本条（交互归入搜索/列表等对应块）。**不要**在同一小节再拆多条仅描述「Tab 齐不齐」的碎句。
- **「与原型一致」尾句只放固定位置**：同一**页面**内，该尾句**仅**出现在 `### 界面与原型一致` 下的那条概括末尾；`搜索`、`列表`、`分页`、`汇总`、`导出` 等小节只写行为、数据、可对账，**句尾不再加**「与原型一致」。**弹窗**可沿用图一条目写法：在 `### 某弹窗` 下用**首条**一句概括「标题「…」、字段顺序、…、与原型一致」，其余各条只写校验与流程，不再重复该尾句。
- **不写推脱句**：不出现「仅有本页原型则以产品说明验收」「无原型时」等**与用例无关**的说明。
- **Markdown 星号**：导出给 XMind 的正文**不用** `**文字**` 当强调；星号易被原样导入，看起来像乱符或误当冒号。需要强调时改用「」或直接短句。
- **圆括号用法**：**禁止**用括号写揣度，如「以产品为准」「除非产品定义为或」「或后台下发的固定值」等；括号只写**已知的限定场景**，例如「（开关行支持编辑时）」「（汇总行为当前页合计时）」。规则不明就**不写括号**，或在需求文档写明后再补。

## 二、列表类页面（预支管理、还款记录等）— 固定四块

凡「筛选栏 + 表格 +（可有）分页」的页，**依次**展开下面四层（脑图子节点顺序保持一致）。

### 1. 界面与原型一致

- **一条概括**：标题、Tab、筛选行、主按钮、表格列与状态色等与原型一致；与同页其他功能混排时仍保持**单条**，不拆成「Tab 一条、列表区一条」两级父节点。

### 2. 搜索（筛选）

- 逐字段列出原型上的筛选项（下拉、文本、日期起止等）；**多条件同时生效**时写清命中关系；需求未写「或」时按**同时满足**写用例。
- 必有「重置」：清空条件并恢复默认列表。
- 必有「搜索」：合法条件下刷新列表。

### 3. 列表（表格）

- **逐列列出**表头展示字段；有状态色、图标（如已还清√）的写清颜色与文案；本小节**不用**句尾「与原型一致」（版式对照已在「界面与原型一致」一条写毕）。
- **必有**：列表数据与**数据库/后台记录**一致（或与接口返回字段可对账）。
- **原型便签为「纯数据记录，不多做说明」**时：本块**保持精简**——不强行展开复杂业务推导，以**展示正确、可对账**为主。
- **还款记录特例**：若有「汇总」行，补一条汇总列与列表数据规则一致（分页时按需求文档是当前页还是全量）。

### 4. 分页组件

- 统一的 **5～6 条** 范式（每个列表页复用）：
  - 能翻**上一页/下一页**（或分页器）；
  - **总条数**展示正确；
  - 能 **跳转到指定页**；
  - **超限页码**（如超过总页）有拦截或自动纠正；
  - （可选）每页条数切换若原型有则补上。

## 三、预支白名单（复杂页）— 在四块基础上扩展

在 **二** 的四块之外（或并列），增加 **「新增」「操作」** 分支。

### 1. 新增（表单）

- **必填**：标红星字段（如 **所属平台**、**渠道账号**、**预支上限**）未填时无法提交，并有**明确报错/提示**（写清原型话术更好）。
- **预支上限**（若原型便签：仅**非负整数**，**禁止小数**，**最小 0**，当前**无上限**或按最新产品）：
  - 输入 **0**；
  - 输入合法大整数（如 **100000**）；
  - 输入**非数字**、**中文**、**负数**、**小数** —— **无法提交**或**及时校验**（按产品）。
- **预支功能开关** + 说明文案：与原型一致；**关闭**且**存在未还款**时：仍**可还款**、**不可再预支**（与渠道侧菜单显隐规则一致，见下条）。

### 2. 操作

- **编辑**：能打开编辑弹窗/页，回显正确，保存后列表与库一致。
- **删除**：先弹出 **「您确定要删除该条信息吗?」**（或原型定稿），**取消**不删，**确定**后记录消失且库中无（或逻辑删除符合定义）。

### 3. 成功反馈（原型便签）

- 点 **「确定」** 保存成功：**关闭弹窗** + **弱提示**（Toast 类）成功（具体文案按原型）。

### 4. 开关与渠道侧行为（黄框业务）

- **开启**：侧端**预支功能菜单展示**，用户**可预支**（在额度规则内）。
- **关闭且无欠款**：**菜单隐藏**，不可新预支。
- **关闭但有未还清欠款**：**菜单仍可见**，用户**仅可还款**、**不可新预支**。

## 五、AI 输出检查清单（每次写新模块前自审）

| 项 | 是否覆盖 |
|----|----------|
| 顶层模块与原型 Tab/菜单 **一一对应** | ☐ |
| 列表页是否按顺序写：**界面 → 搜索 → 列表 → 分页** | ☐ |
| 搜索是否含 **重置** + 各筛选项 | ☐ |
| 列表是否含 **列清单** + **与库一致** | ☐ |
| 分页是否用 **统一范式** | ☐ |
| 表单是否含 **必填、边界、非法字符** + **成功弱提示** | ☐ |
| 删除是否含 **二次确认** 文案 | ☐ |
| 业务特例（白名单开关+欠款）是否单列 | ☐ |
| 「界面与原型一致」是否通常为一条概括 | ☐ |
| 测试点正文是否避免 `**` 与猜测性括号 | ☐ |
| 同一弹窗/表单是否单一 `###` 下列表展开 | ☐ |
| 搜索字段是否与手写/需求一致（未照抄错误原型列） | ☐ |
| 下拉类是否含搜索、选中、去除三步 | ☐ |
| 数字字段是否含典型合法多点、非法点、框下文案 | ☐ |
| 每个必填项是否各有「未填点确定→提示」 | ☐ |
| 批量删是否分无勾选/有勾选；删前文案逐字 | ☐ |
| 删前确定是否分批量与单行两条 | ☐ |
| 行内开关是否分字段写切换 | ☐ |
| 编辑保存是否可按首充/续充分条 | ☐ |
| 分页是否含条数切换、点页码跳转（若有） | ☐ |
| 月卡等业务是否落到场景一二三与具体金额与天数 | ☐ |

## 六、Markdown 与 XMind 导入（对齐版本一）

- **与版本一《测试点生成规则》一致**：`*.md` 用标题 + 列表表达脑图，便于 XMind 或本仓库 `md_to_xmind.py` 导入；禁止仅以 fenced 代码块承载整棵树作为唯一结构。
- **层级约定（与当前解析脚本兼容）**：
  - `#`：文档中心主题；`<!-- 笔记：… -->` 紧跟其后。
  - `##`：脑图一级分支（如「xxx 模块测试点」与「检查清单（版本二自审）」并列）。
  - `###`：二级主题；同一业务单元下**优先少而整**，见下条。
  - `###` 下 `- ` 列表：末级测试点，一条一句。
- **`###` 合并原则（减负）**：同一弹窗、同一表单、同一流程，**只用一个** `###` 父节点，其下用多条 `- ` 分字段/分步骤写；**避免**平行挂一串「新增弹窗-游戏名称」「新增弹窗-渠道账号」多个 `###`。列表页仍按「界面与原型一致 → 搜索 → 列表 → 分页 → 工具栏/行操作」拆开，每块一个 `###` 即可。
- **与「八、手写差异补充」的关系**：若对手写脑图需覆盖「搜索回填与去除、多必填逐个提示、删前确定拆批量/单行」等，同一 `###` 下允许**较长列表**；**不得**为强行「少节点」而删掉手写已有维度。
- **深层标题**：工具不解析 `####` 时，勿把内容只写在 `####` 里；改为并入 `###` 下的列表。
- **检查清单**：`## 检查清单…` + `###` + `-` 列表；不用 HTML 表格充当导图节点。
- **可选**：文末「附：树形缩略」代码块仅供对照，不能替代正文结构。
- **正文禁用 `**` 强调**：与「一、简洁与粒度」一致，避免导入脑图后出现星号噪声。
- **禁用 Markdown 水平线**：测试点交付的 `*.md` 中**不要**使用单独占一行的 `---`（部分导入方式会把它当成正文节点）。大段之间用**空行**分段即可。

详细理论层次仍参阅：`版本一\测试点生成规则.txt` 中「Markdown文件层级结构 / XMind格式」说明。

## 八、手写用例与 AI 初稿差异补充（代充折扣类页）

以下来自对手写脑图与 AI 初稿的对照（你文末写「代充记录」但内容为「代充折扣」时，以**实际模块**为准，避免文题不符）。

### 1. 筛选字段以谁为准

- **手写作准**：手写已列出「所属平台、所属渠道、游戏名称、添加开始与添加结束时间」等，则 AI **不得**照搬错误原型里的无关项（如本模块不应出现的「还款编号」「关联预支」等）。
- 可先写一条**总括**：能通过 A、B、C、时间范围筛选到目标折扣；再按需拆条或合并。

### 2. 搜索与重置的写法

- **重置**：除「恢复默认列表」外，手写常写 **「点击重置，能够清空输入框的搜索条件」**，便于执行与提缺陷。
- **多条件**：仍按「同时命中」写；不写猜测性括号。

### 3. 新增与弹窗（粒度）

- **入口**：点击「新增」能打开新增弹窗（独立一条或与弹窗首条合并均可）。
- **弹窗壳**：标题文案、点「×」关闭、点「取消」关闭 —— **宜分条**，不宜只写一句带过。
- **可搜索下拉的三个动作**（游戏名称、渠道账号等）：能搜索且下拉展示结果；能选中并回填；能**清除/去除**已选（手写必备，AI 易漏）。
- **只读项**：写清展示值（如 10.00折）与「无法修改」。
- **数值折扣**：除区间与非法值外，手写会列**典型合法**多点（如 1.00折、5.01折、10.00折）与**典型非法**（0.99折、10.01折）；并写 **「输入框下方的说明/提示文案」** 与界面一致。
- **必填全覆盖**：除游戏、渠道外，**每一个**必填数字项单独一条——未输入时点确定有明确提示（如渠道首充折扣、渠道续充折扣），AI 勿合并为笼统一句。
- **成功路径**：已填合法信息点「确定」→ 关窗 + 列表新增可对账。

### 4. 批量删除与无勾选

- **无勾选**点击批量删除：有「需先勾选」类提示，列表不变。
- **有勾选**：弹出二次确认；与**单行删除**分支分开写（见下）。

### 5. 二次删除确认

- **文案**：与产品/原型**逐字一致**；「请谨慎操作」与「请慎重操作」以定稿为准，不擅自替换。
- **取消**：不删、关窗。
- **确定**：宜拆两条——**仅删批量勾选记录**；**仅删当前行操作列对应记录**，均关窗且库表一致。

### 6. 列表与行内开关

- **列清单**：与手写或表头一致；**复选框**仅在实际存在时写入。
- **行内开关**（如渠道首充状态、渠道续充状态）：**分字段**写「点击能在开/关间切换」；不宜合并为一句带过（除非产品定义为只读）。
- **对库**：保留列表与数据库记录一致。

### 7. 操作列-编辑

- 点击编辑打开编辑弹窗。
- **保存**：按手写习惯可按**字段**分条——修改渠道首充折扣后点确定能保存；修改渠道续充折扣后点确定能保存（与「一句概括保存」相比更利执行）。

### 8. 分页组件

- 在手写覆盖处补充：**每页条数可调**（若页面有）；**点击页码直接跳转**；**上/下页**；**总条数**展示；与 AI 原「仅上下页+总条+输入跳转」相比更贴近真实页。

### 9. 配置生效与会长代充（业务向）

- 手写常在列表页后追加 **「未配置/已配置 + 会长首续充 + 绑币/平台币」**，属**业务验收**或**联调**类点：如未配置游戏会长首充/续充均为 10 折；已配首充 5 折则绑币与平台币首充均为 5 折；已配续充 6 折则绑币与平台币续充均为 6 折。
- AI 出后台列表用例时：若需求含 C 端生效，应在同文档增加 **「### 业务生效」** 或另建 **业务测试** 分支，避免只验后台表不验折扣落地。

### 10. 脑图节点顺序（可选）

- 手写常见顺序：**界面 → 搜索 → 新增（含弹窗子树）→ 批量删除 → 二次确认 → 列表（含开关、编辑子树）→ 分页 → 业务生效**。导出 MD 时 `###` 顺序可向其靠拢，便于和已有 XMind 对照。

### 11. 业务测试点具象到可执行场景（月卡类等）

- 除抽象规则外，宜写清：档位金额、绑定的礼包或福利名称、玩家代号、各笔充值金额与顺序、日历第几天与「月卡第几天」奖励的对应，便于按日造数验收。
- 多组情况用 **场景一、场景二** 等分列；父节点为场景名，子节点为可观察结果（领奖、停发、仅最高档不计低档等）。
- **当日升档**（已领当日礼包后再升档）：新档礼包当日不补发，**新周期自次日 0 点起算**；与「首次激活、周期结束后重新激活」的当日立即发首包区分开，避免写反。
