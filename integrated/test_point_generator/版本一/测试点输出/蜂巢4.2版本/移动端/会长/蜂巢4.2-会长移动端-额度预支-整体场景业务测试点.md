# 蜂巢4.2-会长移动端-额度预支-整体场景业务测试点

## 业务测试

### 会长移动端

#### 额度预支-整体场景

##### 场景1：额度三角「可用+已预支=总额」在预支/还款全链路不破坏

- **前置**
  - 会长已登录；能进「**额度预支**」；后台或造数能控制**总额度、已预支、可预支** 及预支/还款记录。

- **操作与验证(连贯)**
  - 初始在仅展示「我的额度」时，**可预支、总额、已预支** 与接口一致，且 **可预支 + 已预支 = 总额度**（以产品公式为准，排除原型里三数不闭合的笔误样例）。
  - 在**代充/会长代充**路经「**去预支**」完成**一笔**新的额度预支(例：预支 **5000** )后，回到本页刷新：**已预支** 与 **可预支** 同步变化，**总额** 不变，**等式**仍成立。
  - 该笔在「**预支记录**」出现新 **YZ** 行：待还=预支额、已还=0、状态=**待还**；与「**关联代充**」单号**一致可跟踪**。

##### 场景2：多笔待还+余额从「有到无」的「立即还款/一键还款」与冲账顺序(便签1 III)

- **前置**
  - **预支记录** 中至少 **3** 条 **待还**，**预支时间** 分别为 T1(最早) < T2 < T3(最晚)；会长**余额**为 B，**0 < B** 且 **B <** 三笔**待还之和** 且**至少能完全还清 T1+T2**、对 T3 仅能部分(或按你造数微调)。

- **操作与验证(连贯)**
  - 从**一键还款**(因 ≥2 笔)进入 **确认还款**，**本次还款总金额** 为 **B**(或与「余额与待还取小」的定稿一致)；确认后成功弹窗**全额还款笔数+部分还款笔数+还款金额= B** 可对账。
  - 回「**预支记录**」：T1、T2 **已还清**；T3 **待还=原待还-末段冲账**；**冲账顺序** 严格 **按预支时间从早到晚**。
  - 在「**还款记录**」**新增 1 条或多条** **HK** 流水(若一确认拆多 HK，则按接口)；每条**关联预支** 能对应到被冲的 YZ；**时间顺序** 与**扣款**一致。

- **子场景：余额=0 再点**
  - 将余额**扣至 0** 后，**立即还款** 与 **一键还款(若仍可见)** 均提示「**余额不足，无法发起还款**」类文案，**无** 成功**还款** 记录新增。

##### 场景3：仅 1 笔待还时，「一键还款」不触发批量流；2 笔起触发

- **前置**
  - 造数仅 **1** 条待还 与 **2** 条待还 两种环境各测一轮。

- **操作与验证**
  - **1** 条时：底部**一键** 区域为**置灰/隐藏**(与定稿一)；**仅** 能用该行「**立即还款**」进单条确认。
  - 增至 **2** 条时：**一键** 可点，**确认** 弹层副文案(例**共2笔**… )与两笔**合计/顺序** 一致。

##### 场景4：确认还款 → 成功弹窗 → 查看记录/关闭(便签4) 的闭环

- **前置**
  - 能完成**任意一次** 有效扣款(单条或一键)。

- **操作与验证(连贯)**
  - 在**确认**前记下**点按瞬间**的「剩余 **¥**」与主账户可用余额(同一余额池)一致；扣款后「**当前余额**」= 前余额 −**还款金额**。
  - 若本次**只发生全额结清、无** 部分结清：成功弹窗**不** 出现 **「部分还款0笔」** 整行(或等价隐藏)；**仅** 部分 时反隐藏。
  - 点 **「查看记录」**：弹窗**收** 且**落地「还款记录」** 列表，**最上/按时间** 可见刚生成的 **HK**；点 **「关闭」** 不跳转、留在**原页** 且**列表已刷新**。

##### 场景5：同一 YZ 下「分两次还」的 HK 与「全额/部分」标签(便签5)

- **前置**
  - 单条预支 **YZ**、预支额 **A=10000** ；先保证余额足够**两次** 操作。

- **操作与验证(连贯)**
  - 第一次**仅**还 **2000** → **还款记录** 新增 1 条：还款额 **2000**、类型 **部分还款(黄三角)** 、**关联预支=该 YZ**、编号 **HK** 规则 正确；**预支记录** 该 YZ 待还=**8000**。
  - 第二次还**剩余 8000** → 再**新增** 独立 **HK** 行；第二笔在「类型」为 **全额还款(绿勾)** 当且仅当 产品定义「本**还款记录**金额=**该笔**冲抵后相对**本预支**原额」—即若业务规定「**第二笔=8000 仍算部分/全额** 依 **是否=原始预支额 A**」按便签5：**还款金额(2000) ≠ A** → 部分；**第二笔(8000) ≠ A** 仍**部分**；只有**单条还满 A** 或产品另有「**结清**即全额」则按定稿**唯一**断言(团队需对齐**便签5**「与**预支金额**比较」的「预支金额」是**原单 A** 还是**当次分笔**，测试用例**按产品定稿** 写清)。
  - 两笔 **HK** 号**不同**；**关联预支** 同 **YZ**；**剪贴板复制** 不丢字。

##### 场景6：还款记录「筛选(条6)」+「搜索」与 **且** 组合

- **前置**
  - **还款记录** 中**至少 2** 条，分布在**不同日期** 或 不同**全额/部分**、保证筛选可**区分**。

- **操作与验证(连贯)**
  - 选**近7天+全额还款+余额支付**，点**确认** → 列表**仅** 命中 交集；**筛选(N)** 的 **N** 与 顶部**标签** 数一致；**点× 删 时间** 条件后 列表**重算** 且**不** 关面板若仅删标。
  - 在「**搜索编号**」输入某 **HK** 子串，能**唯一定位** 或 列表有**高亮/过滤** 行为与产品一致；与**筛选项** 同时生效时为 **且** 关系。
  - 故意组合出 **0 条** → 出现「**暂无符合条件的还款记录**」。

##### 场景7：App 与 Web/其它端(若存在)数据一致(选测)

- **操作与验证**
  - 同会长在**网页端** 或 另一 设备 **App** 上完成一次 **预支/还款** 后，本页 **15s 内/下拉刷新** 后 **YZ/HK/余额** 与对端**一致**（以产品**延迟** 说明为接受范围）。

## 可导入为场景摘要的短句

- **可用+已预支=总额** 全程成立；去预支→代充→**预支**后三数、YZ 对账  
- **≥2 笔** 才有一键；**0 钱** 双按钮均拦截，文案「余额不足，无法发起还款」  
- **多笔** 还：时间**从早到旧** 冲、**前整后零** 末笔可**部分**  
- 成功弹窗 **0 笔的统计行不展示**；**查看记录=还款 Tab** ；**关闭=留**  
- **HK/YZ 规则、全额/部分** 与便签5、**筛选 且 组合** 与 条6
