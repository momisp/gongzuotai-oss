# token刷新业务场景测试点

## 场景35：apptoken刷新流程验证

### 前置条件
- 用户已登录，拥有有效的access_token和refresh_token
- token即将过期（如剩余5分钟）

### 测试步骤（后端主动刷新）
1. 启动抓包工具（Charles或Fiddler）
2. 观察后端日志，确认后端检测到token即将过期
3. 等待后端主动发起刷新请求
4. 抓包查看刷新请求的详细信息（URL、方法、请求头、请求体）
5. 抓包查看刷新响应的详细信息（状态码、响应体，包含新的access_token和refresh_token）
6. 验证后端是否正确获取和存储新token
7. 验证后端是否通知客户端使用新token
8. 客户端发起一个需要认证的API请求
9. 抓包查看请求的请求头，确认使用的是新token
10. 抓包查看请求的响应，确认请求成功（返回200或其他正常状态码）

### 测试步骤（客户端主动刷新）
1. 准备一个即将过期的token（如剩余5分钟）
2. 启动抓包工具（Charles或Fiddler）
3. 客户端发起一个需要认证的API请求
4. 观察客户端日志，确认客户端检测到token即将过期
5. 等待客户端主动发起刷新请求
6. 抓包查看刷新请求的详细信息（URL、方法、请求头、请求体）
7. 抓包查看刷新响应的详细信息（状态码、响应体，包含新的access_token和refresh_token）
8. 验证客户端是否正确获取和存储新token
9. 客户端使用新token继续发起API请求
10. 抓包查看请求的请求头，确认使用的是新token
11. 抓包查看请求的响应，确认请求成功（返回200或其他正常状态码）

### 测试步骤（新token使用验证）
1. 完成token刷新后，立即发起一个需要认证的API请求
2. 抓包查看请求的请求头，确认使用的是新token
3. 抓包查看请求的响应，确认请求成功（返回200或其他正常状态码）
4. 使用旧token发起一个需要认证的API请求
5. 抓包查看请求的响应，确认请求失败（返回401或token过期错误）
6. 验证旧token在刷新后立即失效

### 测试步骤（异常场景）
1. 使用过期的refresh_token发起刷新请求
2. 抓包查看刷新请求的响应，确认返回401或token过期错误
3. 验证客户端是否正确处理错误（跳转到登录页面）
4. 验证本地token是否正确清除

### 验证点
- 后端能够主动检测token即将过期并发起刷新请求
- 客户端能够主动检测token即将过期并发起刷新请求
- 刷新请求的URL、方法、请求头、请求体格式正确
- 刷新请求的响应包含新的access_token和refresh_token
- 新token能够正确存储和更新
- 新token能够正常使用进行后续API请求
- 旧token在刷新后立即失效
- 使用旧token的请求能够返回401或token过期错误
- token刷新失败时能够正确处理错误
- 抓包能够完整记录token刷新的完整流程
- 抓包能够看到后端刷新请求和客户端刷新请求
- 抓包能够看到新token的使用流程
