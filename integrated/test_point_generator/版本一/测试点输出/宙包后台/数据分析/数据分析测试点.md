## 测试数据造数说明

### 一、用户性别分布

**1. 数据模型**
- 在指定时间范围和用户类型下，按性别统计去重用户数
- 需准备：用户表(含性别字段：男/女/未知)

**2. 造数步骤**
1. 为用户填充性别(男/女)，部分用户留空或设为"未知"
2. 按用户类型筛选(全部用户/新用户/活跃用户)
3. 在时间范围内对用户去重计数，得男、女、未知数量
4. 总用户数 = 男+女+未知；占比 = 该性别数/总用户数×100%

**3. 验证场景**
- 某性别为0 → 不显示该扇区
- 某性别占比<5% → 合并到"其他"(若已配置)
- 全部为未知 → 仅显示未知扇区100%
- 用户类型切换 → 新用户/活跃用户数量与全部用户逻辑一致

---

### 二、用户性别趋势 / 用户年龄趋势

**1. 数据模型**
- 按日 + 用户类型 + 性别/年龄段 生成去重用户数
- 需准备：用户表(含性别、出生日期)、用户活跃/付费行为表

**2. 造数步骤**
1. 在用户表为每个用户维护性别(男/女/未知)、出生日期
2. 按"首次使用日期"或"活跃日期"维度，统计每日各性别/年龄段的去重用户ID
3. 年龄计算：`年龄 = 当前统计日期 - 出生日期`，映射到年龄段
4. 去重规则：同一用户ID当日多次行为只计1次

**3. 验证场景**
- 同一用户当日活跃3次 → 只计1
- 跨日活跃 → 两日各计1
- 无活跃日期 → 不纳入统计

---

### 三、用户年龄分布

**1. 数据模型**
- 在指定时间范围和用户类型下，按年龄段统计去重用户数
- 年龄来源：身份证号或注册信息中的出生日期

**2. 造数步骤**
1. 为用户填充出生日期(或从身份证解析)
2. 按统计日期计算年龄并划分到：17岁以下、18-24、25-29、30-39、40-49、50岁以上
3. 在时间范围内对用户去重计数

**3. 验证场景**
- 出生日期缺失 → 归入"未知"或排除
- 边界值：17岁生日当天、24岁生日当天等

---

### 四、地域分析

**1. 数据模型**
- 用户表需有省份字段
- 在时间范围内统计各省份去重用户数

**2. 造数步骤**
1. 为用户填充省份(福建、广东、浙江、江西等)
2. 部分用户省份为空 → "未知"
3. 总用户数 = 各省份用户数之和
4. 占比 = 该省用户数 / 总用户数 × 100%

**3. 验证场景**
- 单个省份占比100%
- 多省份均衡分布
- 无地域信息用户("未知")占比

---

### 五、付费转换率

**1. 数据模型**
- 每日：付费用户数、分母用户数(访问/新增等)
- 公式：付费转换率 = 付费用户数 ÷ 分母用户数 × 100%

**2. 造数步骤**
1. 确定分母定义(如：当日访问去重用户数)
2. 设定目标转换率(如30%、50%)
3. 反推：`付费用户数 = ROUND(分母用户数 × 目标转换率 / 100, 0)`
4. 示例：分母1000、目标30% → 付费用户数=300

**3. 验证场景**
- 0%：付费用户数=0
- 100%：付费用户数=分母
- 分母=0时的异常处理
- 小数百分比四舍五入(如39.7%→40%)

---

### 六、留存分析

**1. 新用户首次使用留存**
- **首次使用**：新用户首次使用产品的日期
- **新用户数**：该日期首次使用的去重用户数
- **第N天活跃**：首次使用后第N天产生有效活跃行为的去重用户数

**2. 造数步骤**
1. 为用户生成"首次使用日期"
2. 为用户生成后续N天的"活跃日期"记录
3. 第N天留存率 = 第N天活跃用户数 ÷ 首次使用新用户数 × 100%
4. 未到期数据不展示(如2月7日首次使用，2月8日才能算第2天留存)

**3. 自定义留存**
- 汇总：周活跃用户、人均启动次数、累计启动用户
- 表格：日期、留存用户、新用户、留存率=留存用户/新用户×100%
- 按来源(大派队APP、宙包等)分别造数，验证筛选联动

**4. 验证场景**
- 对角线填充：仅显示已到期留存
- 留存率0%、100%
- 新用户=0时的异常处理
